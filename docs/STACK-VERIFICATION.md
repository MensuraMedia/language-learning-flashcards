# Stack, modularity and universality — verification

Audited **2026-08-07** by measurement, not by reading the design docs. Module
line counts refreshed **2026-08-08** after the content expansion; the structural
findings (zero cycles, zero platform checks, zero network references) were
re-run and still hold. Every
figure below came from a command run against the working tree.

---

## 1. Technology stack

### Runtime dependencies — three declared

```toml

```

**33 packages** in the entire installed closure, including test tooling:

**No `node_modules`. No build step.** Verified: zero `package.json`,
`webpack.config.js` or `vite.config.*` in the tree.

| Asset | Size |
|---|---:|

| `study.js` | 571 lines |
| `dashboard.js` | 473 lines |

identifier rather than a fetch. The application works with the network unplugged.

## 2. Modularity

### 6,576 lines of Python across 29 modules

Roughly a quarter of that is generated character data (`content/kanji_n1..n4.py`
and `kanji_frequency.py`), not hand-written logic.

Internal dependency graph, generated by AST inspection of relative imports:

| Module | LOC | Depends on |
|---|---:|---|
| `models` | 142 | — |
| `config` | 153 | — |
| `scoring` | 161 | — |
| `audio_library` | 337 | — |
| `tts_elevenlabs` | 200 | — |
| `tts_voicevox` | 263 | — |
| `content.confusions` | 60 | — |
| `db` | 347 | config, models |
| `analytics` | 576 | db |
| `session` | 347 | content, db, models, scoring |
| `games` | 301 | content, db, models |
| `audio` | 614 | config, db, models, tts_elevenlabs, tts_voicevox |
| `voicelab` | 412 | audio_library, config, content, models, tts_* |
| `app` | 64 | audio, config, content, db, routes |
| `routes.api` | 254 | analytics, audio, db, games, session, tts_voicevox |
| `__main__` | 324 | app, config |

### Verified: zero import cycles

A three-colour DFS over the graph found **no cycles**. The layering is strict:

```
leaves        models · config · scoring · audio_library · tts_* · confusions
    ↓
core          db
    ↓
domain        analytics · session · games · audio
    ↓
composition   routes.api · app · __main__
```

Six modules have **no internal dependencies at all** and are testable in
isolation. The most depended-upon are `models` (9) and `db` (7) — exactly the
two that should be.

### Substitution boundaries

Because coupling runs one way, each of these is a single-module change:

| Change | Touches |
|---|---|
| Swap TTS provider | `tts_voicevox` or `tts_elevenlabs` alone |
| Add a scoring scheme | `scoring.score_attempt()` alone |
| Add an analytics metric | one function in `analytics` + one renderer |
| Add a character set | one module in `content/` + `loader` |
| Add a game mode | `games.MODES` + `GAME_CARDS` |
| Replace the database | `db` alone — nothing else issues SQL except `analytics` and `games` |

### Where modularity is weaker — stated plainly

- **`audio.py` at 614 lines** is the largest module and carries the whole
  resolution chain. It is cohesive but would benefit from splitting the cache
  from the provider dispatch.
- **`analytics.py` at 576 lines** holds 16 metric functions plus deck-shelf
  presentation. `deck_shelves()` and `GAME_CARDS`-adjacent presentation logic sit
  oddly next to pure metrics.
- **The frontend is not modular.** `study.js` and `dashboard.js` are single
  files with no import structure between them, and each re-declares its own
  helpers — which is exactly how the `el()` bug happened (used in `study.js`
  before it was defined there). Shared helpers belong in one module.

## 3. Universality

### Cross-platform — verified

```bash
grep -rn "sys.platform|platform.system|os.name|/usr/bin|C:\\\\" --include='*.py'
# → no matches
```

**Not one platform check or hard-coded path in the Python source.** Every
location is derived:

| Path | Derivation |
|---|---|
| Database | `$XDG_DATA_HOME` or `~/.local/share/japanese-practice/` |
| Audio cache | same root, `audio-cache/` |
| API key | `~/.config/japanese-practice/elevenlabs.key` |
| Audition samples | `~/.cache/japanese-practice/voice-audition/` |

All overridable by environment variable (`JP_DB_PATH`, `JP_AUDIO_CACHE_DIR`, …).

pywebview abstracts the platform WebView: GTK/WebKit on Linux, WebView2 on
Windows, WKWebView on macOS. **Only the Linux CPU path has actually been run** —
Windows and macOS are untested, which is a roadmap item, not a claim.

### Graceful degradation — measured

Every optional dependency has a tested fallback. The application has no
hard external requirement beyond Python and SQLite.

| Missing | Behaviour | Measured |
|---|---|---|
| WebKit / PyGObject | Warns, serves in browser mode | ✅ Observed |
| VOICEVOX engine | Falls through to bundled clips | ✅ **20 ms**, zero errors logged, probe memoised |
| ElevenLabs key | Falls through to local TTS | ✅ |
| espeak / pico | Returns a valid silent WAV | ✅ |
| Bundled clips | Synthesises on demand | ✅ |
| Empty database | Dashboard renders a first-run state | ✅ 9 dedicated tests |
| Network | Never used at runtime | ✅ Verified above |

### Cross-browser

No build step, no transpilation target, no framework. The desktop window and a
browser tab load byte-identical assets. Verified in WebKit (pywebview) and
Firefox.

> **Caveat.** Firefox renders the card views blank in headless screenshot mode
> even when the app is correct — a tooling quirk that cost real debugging time.
> Visual verification uses the pywebview window.

### Script-agnostic by construction

The `characters` table stores a glyph plus optional readings and grouping
metadata. **Nothing in the schema, scoring, session engine or analytics is
specific to Japanese** — `script`, `kana_group` and `jlpt_level` are strings.

Adding Korean Hangul or Chinese Hanzi means a content module and difficulty
keys; the engine, analytics and games are reused unchanged. This is why the
analytics were built over a generic `attempts` table rather than kana-specific
columns.

The one Japanese-specific piece is deliberate: `content/confusions.py` and
`session.voicing_siblings()` encode kana phonology to make distractors test real
discrimination. A new script would supply its own equivalent.

### Accessibility

- Full keyboard operation of both the study and game views, not retrofitted
- `focus-visible` styles throughout
- `aria-label` on cards, tiles and options; `aria-live` on transient readouts
- Charts are SVG, so they scale without resampling
- `prefers-reduced-motion` respected by the stylesheet

**Not verified:** screen-reader behaviour, contrast ratios against WCAG.

## 4. Summary

| Property | Verdict | Evidence |
|---|---|---|
| Small dependency surface | ✅ | 3 declared, 33 in closure, no build step |
| No network at runtime | ✅ | Zero external references in shipped frontend |
| Strict layering | ✅ | Zero import cycles; 6 dependency-free leaves |
| Platform-neutral source | ✅ | Zero platform checks or hard-coded paths |
| Degrades rather than fails | ✅ | 7 fallback paths, each tested |
| Script-agnostic engine | ✅ | No Japanese-specific columns or logic in the core |
| Frontend modularity | ⚠️ | Monolithic JS files with duplicated helpers |
| Windows / macOS | ❌ | Untested |
| Accessibility conformance | ❌ | Affordances present, conformance unverified |
